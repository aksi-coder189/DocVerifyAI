# Evaluation and claims

## Current evidence

The repository includes software regression tests for extraction/provenance, the bundled synthetic sample and issuer scenarios, upload/preview/review/delete flow, metadata filtering and citations using a test embedder, cross-document comparisons, retention cleanup, and the optional anomaly baseline. The tests do not use real student records, real policies, or real issuer records. Do not describe their passing as document-verification accuracy.

The Isolation Forest is trained from controlled synthetic feature examples. `scripts/evaluate_anomaly.py` prints confusion counts for a tiny, constructed synthetic smoke set. These values only show the training/evaluation code runs; they are not statistical performance estimates. No real-world precision, recall, F1, AUC, OCR quality, or fraud-detection accuracy is reported.

## Implemented retrieval and extraction

Local Sentence Transformer embeddings are generated by an explicit ingestion command and stored with source metadata in a small JSON cosine-vector index. This avoids a mandatory paid API; embedding weights are an optional external download during explicit setup. At runtime, the model is loaded from local cache only. Citations preserve source title, issuer, page, policy date (null if unknown), passage, and local path. Metadata filters and a relevance threshold produce explicit `insufficient_evidence` responses. The bundled policy corpus is synthetic/illustrative, not official. Test retrieval uses a deterministic fake embedder to avoid downloads.

PDF extraction is page-wise. Image-backed pages with absent or sparse embedded text try local Tesseract OCR through PyMuPDF. After parsing, pages with missing required fields or a visible but unparsed subject-table header receive a quality-based OCR retry; OCR replaces embedded evidence only when structured extraction improves. OCR decisions and fallback diagnostics are retained per page. Field provenance includes extraction method, page, evidence text, and a heuristic or OCR-engine confidence label. Those scores are not calibrated. Subject tables use coordinate-clustered PDF/OCR word boxes and explicit cell separators where available, including wrapped names and repeated tables. The bundled synthetic marksheet contains three fictional rows to exercise this parser. Board/document schemas are extensible configuration, not exhaustive parsers for every issuing authority.

## Objective checks and machine signals

Deterministic checks remain separate from ML. The Isolation Forest is an optional unsupervised *document quality outlier* baseline, not an authenticity or fraud classifier. It persists via joblib and returns the score plus largest robust feature deviations. No classifier was trained on real cases; no fraud probability is emitted.

Cross-document checks compare names across uploaded records and roll numbers only within selected document families. They preserve page/evidence references and return inconclusive when confidence is low. This is a screening aid; it does not resolve identity.

## Metrics for future labeled data

When appropriately licensed and representative labeled data exists, report field precision/recall/exact match/calibration by field, document family, and OCR path; retrieval Recall@k and citation correctness; anomaly precision/recall/PR-AUC/false-positive rate; latency/failure rates; sample counts and confidence intervals. Split by issuer/template and time to limit leakage. Keep synthetic and real results separate. No such real dataset currently exists.

## Synthetic university-document alteration examples

`backend/datasets/university_documents_synthetic.jsonl` provides paired text-only examples for 12 university document families. It includes deliberately planted single-field value changes, not real forged records. The `synthetic_unaltered` and `synthetic_field_altered` labels describe construction only; they are not authenticity labels. Use the corpus for parser and planted-change regression checks only, keep results separate from real data, and do not train an authenticity classifier from it. See the dataset README for fields and limits.

## Marksheet consistency checks

The report can flag marks beyond the printed maximum, conflicting duplicate subject rows, and subject marks that differ between two uploaded marksheets when roll number and exam year match with adequate extraction confidence. These checks show both source references and are useful for prioritizing human review. OCR, layout, correction, or legitimate record updates can also explain a discrepancy. Uploaded copies are not independently verified, so none of these signals establishes authenticity or forgery.
